# Aali Studio on the Mac — where to start

This archive is **source code only**. There is no ready-made `.app` inside:
a PyInstaller app must be built on the OS it will run on, and a macOS `.app`
cannot be produced from Windows. The build on your machine takes a couple of
minutes.

## 1. On the Mac

```bash
unzip HWK-Aali-MAC-TEST.zip
cd HWK-Aali
bash scripts/build_all_macos.sh studio
```

Output: `build-desktop/dist/Aali-Studio.app` — double-click it.
If Gatekeeper calls it "damaged" (only the first time):

```bash
xattr -dr com.apple.quarantine build-desktop/dist/Aali-Studio.app
```

## 2. Test it

```bash
bash scripts/build_all_macos.sh check
bash scripts/build_all_macos.sh check --brain http://192.168.1.13:5055
```

The second form matters: the brain lives on the Windows PC, so the default
`127.0.0.1:5055` on a MacBook points at the MacBook. The check now always
prints the URL it dialled.

This probes **your** machine: config-dir convention, the sandbox, path
escapes, the Arabic renderer, and brain reachability. **Paste me the full
output** — it is the source of truth.

## 3. Already known to work on macOS (your run, 2026-10-03)

`check` passed, on Darwin 25.6.0 arm64 / Python 3.13.7:

- config dir resolves to `~/Library/Application Support/AaliStudio`
- data root is `~/hwk-data` and never points at a missing `D:`
- the sandbox read, wrote, and refused **6/6** escape attempts
- the Arabic CLI renderer produced shaped Arabic and stayed idempotent
- `open_external` rejected a non-http URL

Two real defects that run also exposed, both now fixed:

1. the build died at `BUNDLE` with `FileNotFoundError: icon.icns` — the spec
   demanded an icon that did not exist. `build-desktop/icon.icns` is now
   committed (generated by `scripts/make_icon_icns.py`), and the spec passes
   `icon=None` rather than dying over a cosmetic asset;
2. `check` fell through to the system `python3`, which has no flask, and
   reported a failure that was about the interpreter, not about macOS. It now
   runs on a venv that can actually import the client.

## 4. Run without building (fastest first check)

```bash
python3 -m venv .venv-studio
.venv-studio/bin/pip install flask pywebview
.venv-studio/bin/python build-desktop/aali-studio/studio_app.py
```

## 5. The brain still lives on the Windows PC

Studio on the Mac is a **client**. The model needs the GPU and the
checkpoint. Point it at the PC instead of waiting for one:

```bash
export AALI_BRAIN_URL=http://<ip-of-the-PC>:5055
```

Full details: `docs/PORTING.md` (Arabic, honest per-OS matrix).

## 7. Honest limits

- The `.app` is **unsigned**: the `xattr` line above is the one-time fix.
- The icon is a real `.icns` now, built from the repo's PNGs. It is not
  designed for macOS Big Sur+ iconography — expect a correct but plain icon.
- PyInstaller targets the machine that builds. Build on your Mac for your
  Mac.
- I cannot execute macOS from here, so the build+check after the icon fix is
  still unverified by me. Treat your output as the verdict.
